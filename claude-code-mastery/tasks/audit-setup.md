## Fases de Ejecución

### Fase 1: Check .claude/ Directory Structure

Verifique la presencia y estructura del directorio .claude/:

```
.claude/
  settings.json          # [REQUIRED] Ajustes compartidos por proyectos
  Ajustes.local.json    # [OPTIONAL] Ajustes personales locales (gitignored)
  CLAUDE.md              Instrucciones del proyecto (alt: ./CLAUDE.md)
  reglas / # [RECOMMENDADO] directorio de reglas condicionales
  agentes/ # [OPTIONAL] Definiciones subativas personalizadas
  comandos/ # [OPTIONAL] Custom slash commands
  habilidades/ # [OPTIONAL] Definiciones de habilidad con SKILL.md
  mcp.json               # [OPTIONAL] Configuración del servidor MCP
```

Puntuación de cada elemento:
- Faltan desaparecidos: -20 puntos
- Faltan desaparecidos recomendados = -10 puntos
- Falta de información provisional

### Phase 2: Validate settings.json Schema

1. Lea `.claude/settings.json` y parse como JSON
2. Validar la estructura del esquema:
   - `permissions` el objeto existe con `allow`, `deny`, and/or `ask` arrays
   - `permissions.defaultMode` es un modo válido (askAlways, acceptEdits, autoApprove)
   - Las reglas de permiso usan sintaxis válida de Herramienta(especificador)
   - No hay reglas contradictorias (samo patrón en tanto permiten y niegan)
3. Check `.claude/settings.local.json` si está presente (sélo validación)
4. Check `~/.claude/settings.json` para user-level Ajustes
5. Inhibir cualquier conflicto entre capas de configuración

## Fase 3: Check CLAUDE.md Calidad

1. Localizar CLAUDE.md (ver: `./CLAUDE.md`, `./.claude/CLAUDE.md`)
2. Conteo de la línea de medición (objetivo: bajo 200 líneas)
3. Estructura de comprobación:
   - Tiene cabeceras de marcado para la organización
   - Usa puntos de bala para instrucciones
   - Contiene instrucciones concretas y verificables (no vagas)
4. Compruebe el uso de @imports
5. Comprobar secciones gestionadas por AIOS (si proyecto AIOS)
6. Bandera si más de 200 líneas sin @imports o .claude/rules/ uso

## Fase 4: Lista de ganchos configurados

1. Lea la configuración de ganchos desde settings.json (`hooks` clave)
2. Para cada evento de gancho, documento:
   - Nombre del evento (PreToolUse, PostToolUse, etc.)
   - Tipo de gancho (command, http, prompt, agent)
   - Patrón de empareja (si es aplicable)
   - Valor de tiempo
3. Comprobar los ganchos recomendados comunes:
   - PreToolUse para validación de comando Bash
   - PreCompacto para la preservación del contexto
   - Parar la limpieza de sesión
4. Si el proyecto AIOS: comprobar si Python se conecta `.aios-core/monitor/hooks/`

## Fase 5: Lista de servidores MCP

1. Lea la configuración de MCP desde `.claude/mcp.json` o settings.json `mcpServers`
2. Para cada servidor, documento:
   - Nombre del servidor
   - Tipo de transporte (stdio, http, se)
   - Comando o URL
   - Variables ambientales (sólo nombres, no valores)
3. Compruebe los servidores recomendados comunes (context7, exa, navegador)
4. Verificar que no hay secretos que se codifican en archivos de configuración comprometidos

## Fase 6: Check .claude/rules/ Cobertura

1. Listar todos los archivos en `.claude/rules/`
2. Para cada archivo de reglas:
   - ¿Qué? `paths:` frontmatter (carga condicional)
   - Documentar los patrones de glob si están presentes
   - Conteo de la línea de medición
3. Evaluar la cobertura:
   - ¿Hay reglas para los directores principales (src/, tests/, docs/)?
   - ¿Las reglas están usando carga condicional cuando sea apropiado?
   - ¿Hay reglas incondicionales que deben ser condicionales?

## Fase 7: Check .claude/agents/ Definiciones

1. Listar todos los archivos en `.claude/agents/`
2. Para cada archivo agente:
   - Verificar la primera máquina YAML está presente y válida
   - Consultar los campos necesarios (nombre, descripción, herramientas)
   - Tamaño de la definición de medida
3. Comprobar posibles problemas:
   - Agentes sin restricciones de herramientas (demasiado permisivas)
   - Agentes con responsabilidades superpuestas
   - Definiciones de agentes que se pierden referencia a otras partes
